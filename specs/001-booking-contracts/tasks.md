## Dependencies and execution order

US3 consumes those identities, membership and attendance, and reuses the US1 retention clock. Each story can run from fixed synthetic prior state without any host. Within US1, T004 fixture authoring and T005 decoding can proceed independently after T003. Within US2, T008 fixtures and T009 membership decisions use separate files. Within US3, T011 and T012 exercise separate fixtures and partial-class files. Run the complete contract suite after integration. Keep implementation, independent code review and verification in their workflow roles.

The scenario catalog stays authoritative. INT-01–06 apply to H10/SAL/CAS. SAL IDs apply to SAL, H10 IDs to H10, CAS IDs to CAS, and BRK/KFK/PDS IDs to all. A pure decision pass contributes contract evidence only. No missing runtime proof, skipped case or unavailable platform is a pass. The later intake/persistence host must prove transaction boundaries, physical erasure, reconciliation and concurrent delivery against PostgreSQL. Feature 002 provides local infrastructure, 003 covers Kafka, 004 covers destination integration and 005 provides coverage visualization.
