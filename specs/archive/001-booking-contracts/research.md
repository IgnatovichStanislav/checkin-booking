# Planning decisions

The Owner approved these choices at G2 on 2026-11-24. Salou is a fictional integration. Its declared behavior can be tested locally. No external PMS clock or real provider was measured.

| Decision | Rationale and alternative considered |
| --- | --- |
| Use .NET 10 LTS, SDK 10.0.404 and C# 14 | The SDK is installed in the worktree environment and available for both target platforms. Pinning the build avoids selecting the installed .NET 11 SDK. [Microsoft SDK release](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) · [support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) |
| MSTest.Sdk 4.5.3 with Microsoft.Testing.Platform | One direct test-project SDK supplies the framework, compatible runner and default TRX extension. xUnit plus separate integration packages offers no required capability here. Pin the project SDK, opt into MTP in global.json and verify the reporter at implementation. [Package](https://www.nuget.org/packages/MSTest.Sdk/4.5.3) · [SDK profiles](https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-mstest-sdk) · [test reports](https://learn.microsoft.com/en-us/dotnet/core/testing/microsoft-testing-platform-test-reports) |
| Represent source instants as UTC ticks | Salou declares whole seconds or 1–7 fractional digits, explicit uppercase Z, strictly later updatedAt for every business change. Equal-time changes remain observable conflicts. Reject unsupported precision before parsing, including 8+ digits. PostgreSQL timestamptz resolves microseconds, .NET ticks resolve 100 ns. Future persistence uses bigint UTC ticks from 0001-01-01 for source and attendance instants requiring exact comparisons. These are timestamps with units, never source revisions. A timestamptz-only design would merge distinct updates. [Npgsql type matrix](https://www.npgsql.org/doc/types/datetime.html) |
| Hotel-local dates with ICU | Validate against a configured list of canonical geographic IANA names and load the selected zone with TimeZoneInfo. Test Europe/Madrid, Europe/Paris and DST date boundaries on Windows and Linux with ICU and tzdata. Fail configuration on invariant mode, unavailable zone or missing ICU. Reject aliases, abbreviations and fixed offsets in the hotel selector. Static offsets would move calendar checks across midnight. [Microsoft globalization guide](https://learn.microsoft.com/en-us/dotnet/core/extensions/globalization-icu) |
| Immutable references and UUIDs | Guid.CreateVersion7 for bookingId as approved, and for guestId as the consistent generator. Never derive IDs from names, time alone or mutable array positions. The scoped key is a tuple. For Kafka use colon-separated UTF-8 components with percent encoding of non-unreserved bytes, including percent and colon, uppercase hex, no Unicode folding. Encode once. Source identifiers must be opaque and contain no guest identity. [UUIDv7](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.7) |
| Versioned HTTP and webhook shapes | OpenAPI 3.1.1 can reference the shared JSON Schema 2020-12 definitions. Pinning that dialect lets reviewers validate the contracts without choosing a web framework. Runtime cross-field comparisons stay explicit. [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html) |

Scope subscription URLs to a hotel and require separate management permission. Use a configured API key in the Authorization header using a Bearer scheme, HTTPS callback endpoints and pre-provisioned signing keys. Rotate by public key identifier, with an explicit old/new verification overlap. Restrict outbound targets to provisioned hotel endpoints. Verify HMAC-SHA-256 over the ASCII decimal Unix send time, a dot and the exact UTF-8 request bytes. Send integer timestamp, key ID and lowercase hex MAC in distinct headers. Compare in constant time, permit five minutes of clock skew, deduplicate the stable notification ID across attempts. Each attempt gets a fresh signature/time. During overlap choose the active key for new attempts, retain old verification keys for the skew window after the last old-key attempt. Runtime secrets live only in root secrets/ files. [HMAC](https://www.rfc-editor.org/rfc/rfc2104.html)

Delivery states are pending, delivered and failed. A successful 2xx response delivers the notification. A timeout, 408, 429 or 5xx remains pending while attempts remain, then fails. Other final HTTP responses fail immediately. Do not follow redirects. Use five delivery attempts with 5s, 30s, 2m and 10m delays measured from each failed attempt. An authorized retry reopens a failed delivery under its existing notification ID and starts a new attempt series. Disabling stops new scheduling. An already received callback may arrive late. The notification transition and outbox row share one transaction; delivery attempts have separate history. Destination registration uses its own approved five-attempt budget. Delivery never mutates a registration.

The approved C02 decision in data-model.md exposes a null current tuple only when there is no applicable operation. A later policy change cannot hide pinned or confirmed work. Apply the approved summary priority to present active statuses. All-active-disabled with no operations yields null. If some active guests lack an operation and all remaining active guests completed, return null so completed still means every active guest completed.
